PenguinCAM Roadmap

Development priorities and future enhancements for PenguinCAM.

✅
Current Status: PenguinCAM is deployed and production-ready at penguincam.popcornpenguins.com

New in 2.0

The latest release rebuilds PenguinCAM around a step-by-step wizard that runs entirely inside Onshape, with support for cutting several parts in a single job:

🆕

Embedded Onshape Panel

The whole workflow runs in a panel docked to your Onshape window. Click a face and it imports live — no export, no upload, no separate tab.

🆕

Multi-Part Jobs

Nest several parts on one sheet and cut them in a single program. A visual layout canvas shows the stock, the origin, and every part in place.

🆕

Interactive Layout

Drag to position, rotate with a handle (snapping to 45°), flip parts over, and multi-select with Shift. Live overlap and out-of-bounds checking.

🆕

Raised Bosses & Islands

2.5D machining now correctly preserves raised bosses and islands enclosed inside deeper pockets, and fully clears enclosed through-holes.

🆕

Asymmetric Tube Patterns

Cut a distinct pattern on each face of a tube — for example, larger access holes on one side for bolt heads.

🆕

Light & Dark Theme

The panel matches Onshape's light or dark theme automatically for a seamless look.

Current Features

PenguinCAM is ready for real-world FRC use with these features:

✅

Automatic Detection

Hole identification, pocket detection, and smart feature recognition

✅

3D Visualization

Interactive preview with toolpath scrubber, tool animation, and adjustable playback speed

✅

Multi-Layer (2.5D) Support

Automatic depth detection for parts with partial-depth pockets, grooves, countersinks, and raised bosses

✅

Tube Machining

Square ends, cut-to-length, and mirrored or distinct patterns for aluminum tube

✅

Tool Compensation

Automatic offset for perimeters, pockets, and holes

✅

Smart Tabs

Automatic tab placement and removal for secure parts

✅

Google Drive

Direct upload to team shared drives

✅

Multi-Team

Team-specific configurations via YAML files

✅

Intelligent Pocket Contouring

Area-based strategy to contour large through-cut features instead of full clearing

✅

Standalone Upload

Full wizard available outside Onshape by uploading DXF files directly

Future Enhancements

Planned features in no particular order. Priority and effort are approximate.

1

Chipload-Based Feeds & Speeds Calculation

Priority: High | Effort: High

Current Problem: Feeds and speeds are specified directly in the config, which doesn't scale when changing tool sizes or flute counts. A 3mm end mill needs different feeds than a 6mm end mill, even in the same material.

Proposed Solution: Specify ground-truth cutting parameters (chipload in inches/tooth, preferred RPM, stepdown as ratio of diameter) and calculate all derived values at runtime. The system would compute XY feed, ramp feed, and plunge feed based on tool diameter, flute count, material chipload, machine rigidity class, and engagement type (slotting vs clearing).

Benefits: Settings automatically work for any tool size. More predictable results. Easier to understand and tune (chipload is the fundamental parameter machinists think about). Enables proper support for multi-flute tools.

Impact: New config file format (version 3), refactored feed/speed calculations throughout postprocessor, updated UI to show calculated vs specified values, migration tooling for existing configs. Foundation for the tool library feature.

2

Automatic Nesting (Auto-Arrange)

Priority: High | Effort: High

An "Auto-arrange" button on the Layout step that positions and rotates parts to waste as little material as possible, then lets you fine-tune by hand. Rather than simple bounding-box packing, it would use true-shape nesting so PenguinCAM's irregular FRC parts interlock, keeping every part at least one tool diameter apart so the postprocessor is unchanged. Planned to run in the browser so parts animate into place interactively.

3

Multi-Part 2.5D Jobs

Priority: Low-Medium | Effort: Medium

Today 2.5D mode is limited to one part per job. Lifting that would let multiple multi-layer parts be nested on one sheet, as long as they share a stock thickness. Niche for FRC (2.5D parts are uncommon), so it ranks below feeds/speeds and other functional work.

4

Resume an In-Progress Job

Priority: Medium | Effort: Low

Persist the job (setup, parts, and placements) in the browser so an accidental reload — or Onshape reloading the panel when you toggle light/dark theme — resumes where you left off instead of resetting to the first step.

5

Team-Specific Tool Library

Priority: Medium | Effort: High

Define named tools in the team config (e.g., "2-flute 1/8in end mill", "1-flute 1/8in end mill") instead of just tool diameters. Different tools of the same diameter could have different performance characteristics - a 2-flute tool can typically run faster feeds than a 1-flute. Tool-specific settings could use multipliers on the base material feeds/speeds, or define complete overrides. Would affect UI (tool selection dropdown), config format, and postprocessor. Works best with chipload-based calculation system.

6

Custom Origin Point

Priority: Low | Effort: Medium

Today the G54 origin (0,0) is the lower-left corner of the layout's bounding box. This would let you pick a specific point on a part — for example a corner or a hole center — as the origin, to match how you set work zero on the machine.

7

Per-Team Branding

Priority: Low | Effort: Medium

Customize the UI with team colors, logos, and names from the config file. Would make PenguinCAM feel more like "your" tool.

8

Additional Cloud Storage

Priority: Low | Effort: Medium

Support for Dropbox, OneDrive, or other cloud storage services beyond Google Drive. Would benefit teams not using Google Workspace.

9

G41/G42 Tool Compensation

Priority: Low | Effort: Medium

Use controller-based tool compensation instead of pre-compensated paths. Would allow more precise finished products, especially for bearing holes where 1.125" often ends up too small.

10

Step Through G-code Text in Preview

Priority: Low | Effort: Low

Many gcode preview tools let you step through the gcode text line by line while showing several lines of context alongside the 3D toolpath. It would be good to replicate that. Useful for debugging, maybe less important for students.

Ideas for Consideration

Not committed to the roadmap yet, but worth exploring:

  • Auto-flip during nesting to pack parts even tighter
  • G-code optimization for shorter tool paths
  • Export simulation as video or animated GIF
  • Integration with other CAD platforms (Fusion 360, Inventor)
  • Library of CNC machines with pre-configured settings
  • Custom tab placement (manual positioning)
  • Exclusion zones on the layout for hold-downs and clamps
  • Adaptive toolpath strategies
